# Tower setup and check-ins

An authenticated user can create a tower from a name, 1–3 protocols, one final outcome,
a weekly rhythm, and private visibility, then record a check-in for the current period.
Ongoing and proxy presets, custom protocols, and custom measures are available in the
same setup. Specific dates, other cadences, and a shared named or anonymous preference
can be saved later on the tower.

The check-in stores ongoing values and final completion for that period and can be
updated in place. The summary restates what was entered. It is not a score, streak, or
health claim.

Catalog pins and the existing practice check-in remain. Sharing with another person is
stored as a preference and does not grant access. Database tests for this migration were
not executed in the environment that prepared this note because Docker was unavailable.
